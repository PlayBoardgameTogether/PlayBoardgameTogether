模型设置减少重复顶部指标与预设，快速服务商配置可选折叠，默认突出配置字段；空列表提供需手动保存的内置模拟入口，状态筛选使用按钮组。保留原高级设置、测试、编辑、凭据保留/替换与更多菜单。本轮没有改变模型调用、正式动作、房间、会话与管理权限契约。

## 对局操作反馈与恢复（2026-10-17，0.8.2）

`useMatchSession` 将持久待确认请求与提交/核对/需手动确认三个反馈阶段分开。正常提交使用固定占位的轻量状态行，成功后在同一区域更新文字；不因存在 pending 就显示异常，也不在每步操作插入大型 ActionHint。响应丢失时立即查询原 requestId 的回执；仅回执不存在时按原尝试次数和原请求内容重试，核对失败才显示一个手动确认入口，待确认期间仍禁用正式动作。

提交、自动恢复、手动确认和控制权切换共用同步 ref 锁，避免同一帧连续点击或窗口 focus/轮询在原请求尚未返回时并发查询及重发。回执 accepted 后必须读取包含已应用 revision 的本人权威局面才清理 sessionStorage；读取失败保留恢复记录，刷新后继续核对。保留原身份绑定、代次隔离、服务端规则、请求去重和真实错误反馈，不从较新的 WS revision 猜测本人动作成功。

回归入口 `tests/e2e/match-feedback.spec.ts` 覆盖慢请求、WS 先于 HTTP、重复点击、焦点同步、提交前/后丢响应、回执/局面读取失败、刷新恢复及旧快照交错；完整双人流程继续由 `color-match.spec.ts` 验证。

## PlayBoard 暖阳桌游乐园与沉浸棋桌主题（2026-10-11）

平台根据官方 PlayBoard 视觉设计基线完成全站主题与交互演进，确立「暖阳大厅与沉浸棋桌」双态设计语言及一系列人性化设计规范：

### 1. 暖阳大厅与沉浸棋桌双态设计语言

- **大厅与平台表面（暖阳乐园）**：
  - 背景色采用温暖舒缓的象牙奶油白 (`--bg: #FAF7F2`)，卡片为纯净奶白 (`--panel: #FFFFFF`)，辅以浅燕麦次级表面 (`--panel-raised: #F4EFE6`)。
  - 文字层次选用温润深栗黑 (`--text: #231F1C`) 与高对比次要文字 (`--muted: #675C50`，文本对比度达 6.2:1，超 WCAG AA 4.5:1 要求)。
  - 品牌高亮与核心焦点采用饱满琥珀暖黄 (`--accent: #F5B738` / `#F6C445`)，文字强制使用高对比深褐字 (`--accent-text: #1E1810`)，杜绝低对比金底白字；主导航激活项呈现暖黄胶囊高光。
  - 关键行动召唤（如房间列表「加入」按钮）采用鲜活翡翠绿 (`#10B981`) 配白字（对比度 > 4.6:1），形成明确而自然的行动引导。
  - 控件与卡片形态采用全圆角胶囊药丸（`border-radius: 9999px`）与高亲和力大圆角（`16px–20px`），配合多色软胶标签体系（青蓝、嫩绿、琥珀橙、柔和紫等）。
- **游戏房间与棋桌舞台（沉浸暗色）**：
  - 进入对局或暗色模式时，舞台底色呈现温润黑胡桃木台面质感 (`#141210` / `#181512`)，面板呈现微透暖调深色磨砂材质 (`#201C18`)。
  - 关键行动按钮（如「结束回合」、「准备」）使用亮丽琥珀金胶囊按键，在暗调桌面提供第一视觉焦点。
  - 玩家席位、发言与行动记录使用各参与者的米宝专属色环标识，将视觉重心让位给棋盘与卡牌。
- **主题切换与向下兼容**：
  - 样式统一由 `apps/web/src/styles/themes.css` 调度并映射至全局 Token。保留原生 `data-theme="light"` 与 `data-theme="dark"` 切换逻辑；璀璨宝石与花砖等扩展棋盘继续保留专属桌布色，且受暗调棋桌层级保护。

### 2. 真实性与透明度原则（Authenticity First）

- 严禁在大厅中伪造虚假在线人数（如硬编码的「324 在线」、「98 进行中」等假指标）。
- 只展示系统权威的真实活跃房间数与即时对局状态；没有对局时展示真诚温和的空状态插画与建房引导，保持平台的数据真实与信赖感。

### 3. 个人中心通行证化设计（Boardgame Passport）

- **桌游通行证（Boardgame Passport）卡片**：
  - 告别单调简陋的传统表单，将个人中心头部打造为桌游通行证风格的 3D 立体质感渐变卡片。
  - 醒目标注米宝玩家编号（`#ID` 专属徽章）、加入天数统计、官方认证印章（Passport Stamp）与高质感头像光环。
- **模块化功能卡片**：
  - 账号资料修改卡与密码安全设置卡采用清晰双栏排版，输入框带精巧前置图标与金光聚焦高亮环。
- **人性化反馈系统（Humanized Feedback Alerts）**：
  - 彻底弃用传统在页面底部直接输出干瘪纯文本的做法；
  - 建立专属状态 Alert 卡片组件（`.profile-alert`、`.alert-success`、`.alert-error`），内置状态图标、圆润胶囊形态、柔和主题自适应背景、显眼边框与微阴影，并配合平滑滑入动效。

### 4. 聊天抽屉分段胶囊控制条（Chat Dock Segmented Pills）

- **分段胶囊选项栏（Segmented Pills）**：
  - 将原先生硬丑陋的选项栏重构为现代圆润胶囊控制条，内嵌平滑的微阴影药丸滑块底衬。
  - 标签项激活时采用深色高对比文字与轻微抬升效果，未读消息配以精致醒目的红色小圆点角标（`.unread-count`）。
- **访客友好提示卡片**：
  - 未登录访客打开聊天抽屉时，呈现温暖克制的提示卡片与一键登录胶囊按钮，消除生硬的裸字警告。

### 5. 游戏卡牌与手牌高对比视觉体系（Color Match & 全平台）

- **手牌色彩唤醒**：
  - 在 `@layer theme` 中为红、蓝、黄、绿卡牌重新注入高饱和微质感渐变背景与微阴影，杜绝被通用按钮样式覆写为无色彩米色方块。
- **数值药丸标签**：
  - 卡牌名称与数值标签（`<span>`）改用纯白高亮圆角药丸胶囊，文字采用各牌面专属深色（红牌深红、蓝牌深蓝、黄牌深琥珀、绿牌深绿），瞬间辨识。
- **三态高对比徽标（`<small>`）**：
  - 「可出」：浅薄荷绿底（`#dcfce7`）+ 深森林绿字（`#14532d`，对比度 10.5:1）+ 鲜绿边框；
  - 「已选中」：暖金底（`#fef3c7`）+ 深琥珀褐字（`#78350f`，对比度 9.8:1）+ 亮金边框；
  - 「不可出」：淡灰蓝底（`#f1f5f9`）+ 深板岩灰字（`#334155`，对比度 7.2:1）+ 细轮廓边框；
  - 深色暗调桌面同样配置独立的暗色高亮对比度规则（对比度 > 8.5:1）。
- **动效无障碍与微交互**：
  - 选牌保持 `-6px` 升起动画；在 `prefers-reduced-motion: reduce` 系统设置下自动无位移平视降级，兼容无障碍与自动化测试。

### 6. 规则折叠卡片与支持面板设计（Detail Support Card & Rules Box）

- 游戏详情页支持卡片（`.detail-support-card`）采用可折叠式优雅卡片，带有金黄微光边框反馈。
- 展开后的规则内容盒（`.rules-content-box`）采用柔和次级表面，规范排版字体行高（`line-height: 1.75`），彻底消除低对比与拥挤排版。

### 7. 全平台无障碍对比度规范与 Token 映射

- 消除全站金底白字、浅粉淡字、硬编码纯白；
- 危险操作按钮（`button.danger`）采用高对比深红字（`#b91c1c`），悬浮态实心深红配纯白字；
- 教程指引（`.tutorial-guide`）、开发者表格表头（`<th>`）等全面适配浅色模式；
- 全局次要文字 `--muted` 基线对比度达到 6.2:1，严格满足并超越 WCAG AA 4.5:1 标准。

## 样式所有权与层级（2026-10-05）

唯一平台样式入口为 `apps/web/src/styles/index.css`，声明 foundation → platform → components → games → shell → theme 及固定子层顺序。历史样式先归入对应职责层，保留逐块合并空间；按需加载的社交、后台、资料、开发文档和回放样式加入 components 的固定子层，不随模块加载顺序改变优先级。

新增普通布局、按钮和主题规则不使用 !important；先选择所属层，再限定组件选择器。例外仅为跳转链接隐藏/聚焦和减少动态效果的无障碍规则。游戏桌面 CSS 由扩展拥有：璀璨宝石与花砖的 client/style.css 分别加入 games.splendor/games.azul；不要重新从平台 main.tsx 导入游戏样式。主题通过已有变量与主题层控制平台表面，不统一游戏规则色彩。

游戏可使用 --platform-top-inset 避让平台导航。平台在游戏路由观察导航尺寸并清理 ResizeObserver，扩展不假设桌面/手机导航的固定高度；该变量只表达外壳占用空间。

## 大厅与资料入口（2026-10-01）

主导航只列游戏大厅、我的资料，创建入口位于大厅标题区并进入独立建房页；建房页提供返回大厅。继续游戏和邀请码加入为两块辅助区域，公开房间保留筛选和分页。退出登录放在资料页。按钮文字统一 line-height/text-align，普通按钮与按钮样式链接使用 flex 居中，房间行使用垂直居中；保留卡牌/棋盘专属布局。资料为桌面双列、手机单列，包含内置头像单选、可选中完整账户 ID、昵称/简介和真实对局历史。

2026-10-01 渐进动效与无刷新换页：站内页面链接通过现有 history 路由切换，侧栏保持挂载；内容区域使用 140–220 ms View Transition 交叉淡入，不支持该 API 时仍无刷新切页并短淡入。换页立即禁用离开页面的交互，新页面将焦点移至主要内容；主动导航回到顶部，浏览器前进/后退沿用原生滚动恢复。外部链接、修饰键、新窗口、下载与锚点保持浏览器语义。减少动态效果时直接切页。房间列表、座位、资源与花园面板错开 40/80/120/160 ms 入场，后续项封顶以避免长等待；已有节点的实时更新不重新入场。

第九阶段沿用 React、原生表单与 CSS，无新 UI 框架。2026-10-01 按 [macOS Vibrancy 参考](https://www.stylekit.top/zh/styles/macos-vibrancy) 全站改版：`stage9.css` 提供中性灰基础与既有响应式布局，`apps/web/src/styles/vibrancy.css` 最后加载，负责桌面侧栏、工作区及组件统一。卡牌颜色、棋盘状态与图包仍使用游戏自身语义。

## 璀璨宝石紧凑棋盘（2026-10-02）

splendor.css 仅针对该扩展及包含其桌面的 match-page 调整布局：深绿桌面、金色回合／选择标识、按视口高度限制卡面、库存与贵族并排、四列三层市场、可滚动商会侧栏。经典卡面额外显示 View 中的语义声望／折扣／费用，手机点击卡牌可放大查看。通用按钮多重 :not 选择器曾覆盖游戏间距，游戏控件使用明确限定的选择器修复，不改变其他游戏样式。
