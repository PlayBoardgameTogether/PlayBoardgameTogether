# 同步流量与空闲轮询优化（2026-10-18，0.9.1）

针对前一轮带宽评估，实施三项兼容优化：局面条件读取、社交概要查询合并、空闲时降低轮询频率。没有改动游戏规则、动作/回执事务、数据库结构、资源版本或服务部署。

## 对局校对：未变化时没有正文

`GET /api/v1/matches/:id/view` 返回账户绑定的弱 ETag。只有请求携带的 `If-None-Match` 与当前授权视图相同，才返回 304；不带校验值的旧客户端继续得到原有完整 JSON。响应继续 `Cache-Control: no-store`，不依赖浏览器或 CDN 保存私密棋盘。

校验值根据账户 ID 和完整本人视图计算，包含局面、状态、资源绑定、玩家名称、全部控制者及 AI 状态，不只比较 revision。每次仍执行当前 session/参与身份检查、原一致性快照与视图投影；不会用完成后的服务器缓存绕过权限。弱 ETag 表示相同业务内容，适配 HTTP 压缩及每次不同的 traceId。

SDK 新增 `matchSnapshotIfChanged`，共用原有认证、取消、超时和错误解析；304 不调用 JSON 解析，401/404/503 仍是错误。旧 API 没有 ETag 时继续完整读取。客户端只在当前页面世代内保留最后一次完整 HTTP 视图与校验值，读取失败和卸载清除；15 秒常规校对使用条件请求，初始化、focus、重连、原请求回执核对仍请求完整视图。在途读取继续合并，不改变同 ID 重试和 appliedRevision 恢复规则。

这项改善减少未变化校对的响应正文，保留了服务端的读取和规则投影工作；不能宣称同等降低了对局查询或 CPU 开销。行动后的 WS 完整投影和行动 HTTP 确认继续发送。

## 社交概要：减少数据库往返

保留只读 REPEATABLE READ、活跃账户/session/token/到期检查，将只读身份重验合为一条 JOIN 查询。概要中的好友 ID 政策、关系/未读及最近 50 条邀请合为一个 SQL 语句；身份和邀请的直接读取复用同一 SQL 投影，保留原顺序、活跃账户过滤、关系/成员校验、到期及可修改时间判断。

原 `SocialService.overview` 为 BEGIN + 两次身份重验 + 三次内容查询 + COMMIT，共 7 次 SQL 往返；现在为 BEGIN + 身份重验 + 概要查询 + COMMIT，共 4 次，减少约 43%。这是该服务事务内的调用数，不包含路由认证、一次查询内部的扫描/子查询、索引工作，也不等于整台数据库负载下降 43%。

不新增跨请求概要缓存，好友删除、账户停用、资料/ID 改名、邀请失效和冷却时间变化仍从当前一致性快照判断。写事务原账户/session 锁序、好友关系、消息水位及请求去重保持。

## 前台空闲轮询：有上限地降频

| 场景 | 原来 | 现在 |
| --- | --- | --- |
| 社交概要持续不变 | 每 5 秒 | 有变化后 5 秒；无变化后 10 秒，再到 15 秒上限 |
| 打开的聊天持续无新消息 | 每 5 秒 | 有新消息后 5 秒；无新消息后 10 秒上限 |
| 页面隐藏、浮窗/频道不可见 | 计时器仍运行并跳过读取 | 停止调度；重新可见立即同步 |
| focus、online、visibility 恢复 | 立即同步 | 立即同步并重置空闲退避 |
| 本人成功发送、处理好友/邀请等显式刷新 | 立即读取或被在途读取跳过 | 立即刷新；在途时合并成一次后续刷新 |

下一次读取在上一次完成后调度，慢请求不会重叠。显式刷新高频到达时只保留一个后续刷新；失败恢复正常 5 秒重试，不无限退避。卸载清理计时器、事件和原请求取消；发送错误、未知结果正文/请求 ID、旧消息位置和已读水位继续由原聊天逻辑持有。

稳定空闲阶段，社交概要约从 12 次/分钟降至 4 次（约 67%），聊天约从 12 次/分钟降至 6 次（约 50%）；刚进入时的第一分钟有爬升过程。按 1000 名前台玩家且概要长期不变折算，社交概要约从 200 次/秒降至 67 次/秒；持续有变化时仍维持 5 秒频率。代价是其他玩家的新通知最多等待约 15 秒、新聊天最多等待约 10 秒才被下一次轮询读取，另加实际网络/服务时间；本人操作与游戏 WS 推送不增加这段等待。这里不是实时社交推送或严格送达时间保证。

## 验证与量化

检查范围与结果：

- `pnpm typecheck`、`pnpm lint`、`pnpm build` 通过，包含边界/格式和生产 API/ZIP/worker 检查。最后完善调度清理的微任务边界后，Web typecheck、Web 生产构建及生产实验台排除检查再次通过；最后修改文件定向 ESLint 和 diff 检查通过。
- SDK 传输、single-flight、实时恢复和轮询单测首轮 25 项通过；随后调度器补充“完成与清理之间收到刷新”回归，5 项全部通过。合计 26 个不同目标用例，不将重复执行累加。
- Color Match 与社交目标集成共 49 项获得通过结果。首轮 48 通过、1 项新增测试重复使用已释放的 pg 客户端；删除该测试内多余的重复调用后，保留 4 次 SQL 预算及 50 条邀请权限/排序断言，原脚本定向重跑该项通过。其余 147 项首轮按名称过滤未执行，不算作通过。
- 桌面 1440×900、手机 390×844 共 52 个目标浏览器场景获得通过结果：首轮 48 通过；4 项新增空闲时钟测试修正后定向通过，最终调度边界修复后这 4 项再次通过。虚拟时钟测试现在等待每次响应 JSON 被读取后才推进下一段时间，保持精确的 5 次概要/6 次聊天周期请求断言；计数区分开发 StrictMode 中取消的初次请求，并修正头像夹具的无效枚举。未改变运行时断言要求或跳过失败场景。
- 覆盖两端完整 Color Match、未知结果原请求重试、appliedRevision 旧快照交错、WS 重连、权限撤销、真实公聊交友/私聊持久化、读旧消息未读水位、草稿及 IME；查看本轮桌面聊天与手机操作确认截图。测试均使用系统 Chromium，不代表真实 iOS 或所有浏览器节流策略。

## 范围与后续

本轮没有配置外部 CDN、开启 WS 压缩或改用增量局面。首次加载峰值及每次行动的 WS 流量仍存在，不能把空闲轮询降幅等同于全部带宽降幅，也不能据此承诺新的单机在线人数。继续使用前轮 5–20 Kbps/普通活跃玩家作为容量规划范围，实际应以游戏组合与线上指标修正。
