# ADR-009：独立游戏仓库与锁定集成副本

状态：Accepted，2026-10-25。

## 背景

用户确认所有游戏各自独立建仓、发布，并统一放在 PlayBoardgameTogether 组织，后续游戏也采用该约定。现有 4 个内置游戏直接被 registry、workspace、策略 worker、资源准备和测试引用；6 个在线游戏通过三文件 ZIP 安装，UNO 两种玩法属于同一游戏仓库。直接删除目录会破坏构建及旧对局版本恢复。

## 决定

- 10 个游戏仓库分别拥有游戏规则、棋桌、AI、资源契约、游戏测试、打包工具和说明。平台拥有账号、房间、matches、持久化、通用 SDK、包运行时、安装审核和部署。
- 平台保留锁定的源码集成副本，由 `game-repositories.lock.json` 指向每个游戏仓库完整提交和各文件 Git blob SHA；这些目录是构建/回归输入，不再作为第二处开发来源。CI 比较工作区内容并通过 GitHub tree API 核对远程精确提交，拒绝漂移和未登记游戏。
- 平台引入游戏更新使用 `import-game-repository.mjs`，核对本地游戏仓库 origin 和完整 SHA，导入前拒绝覆盖平台未提交修改；代码审查和必要验证之后交付平台 PR。该工具不执行游戏代码、不自动安装生产包、不修改数据库。
- 独立仓库包含精确来源的 SDK/解析器兼容性测试快照，以支持独立构建，不宣称 SDK 已在 npm 发布。游戏版本各自维护，原有精确规则、资源和历史版本不改号。
- 内置游戏发布可信 npm 集成包，仍由平台审查和构建；在线游戏发布平台可检查的三文件 ZIP、摘要及 release.json，再经管理员审核安装。仓库源码 ZIP 不能在线安装。

## 其他方案

- 直接删目录或改成空 submodule：会破坏当前 workspace、测试准备及在线更新的独立版本构建，不采用。
- 全部内置游戏转换为在线 ZIP：当前 iframe/QuickJS 包不承载已有全部资源、教程、音效能力，属于另一项产品迁移，不在本次分仓中改规则或降级能力。
- 保持两处都能开发：会造成同一版本分叉，拒绝；使用来源锁和 CI 明确唯一维护仓库。

## 影响

仓库所有权和版本发布完成分离，运行单元、公开协议、数据库及 registry 路径保持原状，平台仍可离线使用已检出的集成副本构建。代价是平台 Git 中保留游戏源码快照，并需要显式更新锁。未来在受信任依赖分发、部署和旧版本保留方案完善后，可再替换集成副本的物理存储方式。
