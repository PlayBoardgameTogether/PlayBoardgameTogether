# 管理员后台

## 管理工作台（2026-10-21，0.14.0）

后台沿用现有九个栏目与路由，按「工作台、玩家与权益、游戏与内容、系统维护」分组。桌面将平台入口收至顶部，左侧为可滚动的后台导航；760px 及以下使用单行横滑栏目并自动露出当前栏目，玩家底部导航、主题选择和返回大厅继续可用。账户的徽章与桌游币子页保持账户管理高亮。

总览以真实账户、房间、安装版本和待审数量为主，统计可直达对应管理页，另列接入待办及常用管理入口。标注最近成功读取时间；刷新期间保留已确认数据并禁止重复点击，失败明确显示旧数据并允许重试，不推测实时统计。好友 ID 修改间隔位于总览「平台规则」折叠区，展开后使用原保存与刷新流程。

账户页提供本页结果数量，长账户 ID 默认折叠、展开后可选中复制；启停状态与管理操作分层展示。游戏列表在选择版本前显示是否存在已上架版本；版本页仍按精确版本管理。账户启停、上下架、审核、徽章、钱包、官方 AI 和更新器继续使用原有权限、确认、revision 与 requestId 回执，不新增管理 API 或写入链路。

生产静态界面回归：构建后运行 `pnpm test:admin-ui`，配置集中在 [tests/config](../tests/config/README.md)。真实身份及写操作仍使用原 `pnpm test:e2e` 准备流程；静态测试的合成 DTO 不代表生产统计或真实操作验收。

## 桌游币管理（2026-10-16）

账户列表的「管理桌游币」进入目标钱包，查看余额和流水，填写整数数量与对玩家可见的原因后发放或扣回。扣回不允许透支；未知结果必须重试原操作，不能重复发放。该钱包为平台通用货币，与仅用于 AI 的 AI 点数独立。迁移、限制与重试说明见 [桌游币](coins.md)。

入口为「更多 → 管理员后台」(`/admin`)。使用 role 为 administrator 的既有账户登录；首次管理员仍通过 README 的 `pnpm account -- admin:init` 命令创建，后台不提供自行提权或注册管理员。

「更多」只保留后台和个人模型设置（开发环境另有实验入口）；资源管理、游戏展示从后台导航进入，系统状态从总览快捷入口进入。后台及子页面使用站内导航，不整页刷新，「更多」保留用户展开/收起状态。

## 服务更新（2026-10-04）

2026-10-20（0.13.0）更新页重新组织：首屏展示实际服务器平台版本和一个「检查并更新」操作，提交哈希与诊断收进详情；更新时显示阶段，切换断连时自动重连并明确结果待确认，失败时给出处理建议与复制诊断。请求回复丢失后继续沿用原 requestId 确认，不因轮询成功清除未知结果。未启用托管、停用与待维护分别给出可执行指引，成功后可手动刷新界面。网站配置指南为 `/developers/online-update`；旧更新器缺少版本字段时明确显示未提供。下段保留原上线记录，当前按钮名称与信息层级以此段为准。

后台导航「服务更新」进入 `/admin/updates`，提供一个「立即检测并更新」主按钮。状态显示发布分支、当前/候选版本、最近检测时间及真实更新阶段；发现新版后后台构建，随后暂停新请求、等待在途请求最多 30 秒再切换，超时恢复服务并报告失败。未结束对局和常驻连接不阻塞；连接会短暂断开，对局进度保留，玩家通过原重连恢复。迁移待维护、失败与未启用托管分别明确反馈。仅管理员有读取/触发权限，Origin/CSRF 保持，部署配置不能通过页面修改。生产默认跟踪 main，已有 UPDATE_BRANCH 需由维护者改为 main 并重启；本次有限排空策略首次上线须启用新版 API 和监督脚本。启用与恢复见 [在线更新](online-update.md)。

## 好友 ID 修改规则

总览可设置好友 ID 修改间隔：0–3650 整数天，默认 30，0 表示不限次数。首次自定义不受限制；之后从上次成功改成新 ID 起按每 24 小时一天计算。保存立即对所有账户生效，缩短或延长间隔按原修改时间计算。普通用户在资料/好友页看到当前规则和下次可修改时间，服务端独立强制校验。该设置不授予管理员代改他人 ID 或读取私聊的权限。

执行 `pnpm db:migrate` 应用新增 022。GET/PUT `/api/v1/admin/social-settings` 使用 protocol/social.ts 的严格 DTO、expectedRevision 和 requestId；设置与 ID 写事务共用社交锁及摘要回执，事务内再次检查活跃管理员和会话，失败全部回滚。

## 基础管理

- 总览显示数据库真实的账户、停用账户、开放房间、进行中对局、安装/上架版本和待审申请数量；可手动刷新。
- `/admin/accounts` 按用户名或昵称搜索，20 项游标分页。普通账户可启用/停用，停用原子撤销全部会话并在提交后通过既有 PostgreSQL 通知断开实时连接；启用不恢复旧会话，需要重新登录。
- 后台不能停用管理员账户。管理员账户生命周期、创建账户和密码重置继续使用既有账户 CLI。总览只读取数量，不提供他人私密对局视图或强制关闭房间。

## 游戏管理

- `/admin/catalog` 先按游戏 ID 合并为游戏列表，可按名称或 ID 筛选；选择一个游戏后才显示它的全部精确安装版本，包括已下架及当前运行进程缺少可信规则/资源的版本。返回列表保留筛选，手动刷新保留所选游戏。版本管理说明默认折叠，ZIP 示例与打包说明移至上传弹窗；展示图片和资源管理通过后台导航进入。
- 上架/下架持久化至 game_installations.enabled，成功后立即影响目录和后续新建/开局，无需重启。下架不会删规则、资源、房间或历史对局；进行中的对局继续使用原锁定版本。等待房间不能用下架版本开局，重新上架后可继续。
- 上架要求当前 API registry 有匹配清单和默认资源；生产环境不能上架 developmentOnly。下架不会令整个 API 健康检查或其他游戏大厅失败。
- `/admin/games` 保留原游戏展示图片编辑与预览；`/admin/assets` 保留原资源上传、校验、发布和归档流程。两页共用后台标题、导航和返回大厅入口，当前栏目高亮；加载或操作失败时仍可切换管理栏目。
- `/admin/submissions` 显示游戏接入申请、仓库地址、资料及审核结果，20 项分页。待审申请可记录「资料已审阅」或「拒绝申请」，必须填写纯文本意见；成功后刷新仍保留结果。

## 新游戏与版本更新

现在可在 `/admin/catalog` 点击「上传游戏 ZIP」，选择符合 `boardgame-package-v1` 的包，先检查、识别新游戏或已有游戏更新，再由管理员审核确认发布，无需重启。窗口提供可玩示例与打包说明；普通仓库源码 ZIP 不能直接安装。规则使用有界 QuickJS WASM，桌面是隔离 HTML，真人玩法复用现有房间/动作/结算与版本恢复；声明决策接口的包支持现有脚本/模型 AI，包内可选 PNG 图标/封面/背景随安装自动显示，管理员展示配置仍可覆盖。更新后执行 `pnpm db:migrate` 应用 023/024/025；包持久于 PostgreSQL，备份数据库即可保留源码和桌面，管理员账号生命周期不删除已安装规则。详细格式、限制、API 和更新方式见 [在线游戏 ZIP](../apps/web/public/developer-docs/game-packages.md)。

资料审阅不会自动安装或执行源码。维护者仍需审查可信源码，实现 SDK 契约、注册服务端与客户端、运行适用测试和构建，部署并执行 `pnpm games:sync`；新安装版本之后出现在游戏管理页。同步不会重新启用已下架的既有版本。

在线上传按 manifest.id 识别同一游戏；新版本审核确认后原子上架新版并下架同 ID 的旧版本，替换大厅入口。审核前不改变目录，期间版本或上架状态变化要求重新检查。旧规则、桌面及进行中/历史对局保留精确版本，等待中的旧版本房间不能开局；同版本不同内容仍必须提升版本号。普通 workspace 游戏仍按上面的可信部署流程发布，新版本发布必须保留仍被旧局引用的精确规则与资源。

## 更新与并发

更新后执行 `pnpm db:migrate` 应用 `019_admin_management.sql`，加载新的 API 与前端代码。管理员写请求复用 Origin、session、CSRF 与角色边界；事务内再次检查活跃管理员及有效会话。普通账户与安装版本各有 admin_revision，外部 CLI 状态变更同样通过数据库触发器递增；旧 revision 拒绝并要求刷新。

写请求携带 UUID requestId。同一管理员和请求 ID 的相同命令优先返回原结果，跨目标或不同内容复用返回 REQUEST_ID_CONFLICT；状态、会话撤销、通知和回执一起提交，失败一起回滚。回执不包含密码、session token、CSRF 或秘密状态，目前随管理员账户保留，没有自动清理。界面在本页相同决定重试时保留原请求 ID；刷新后先读取权威状态再决定。

## 官方 AI 与点数（2026-10-16）

2026-10-18（0.11.0）：后台新发布档位改为 token 定价，配置输入/输出基础点价（点/百万 token）、加价比例及单次预留上限，实时预览玩家售价。基础点价由管理员自行换算供应商成本；调价发布新档位。旧固定档位保留原价，token 账单保存用量及价格快照。缺少用量或超出预留免费兜底，不追加扣款。执行迁移 033；下段为首版能力记录，最新规则见 [计费说明](official-ai.md)。

`/admin/official-ai` 从管理员本人已配置真实凭证的模型发布官方 AI，允许开放/停用、编辑、删除、搜索玩家发放 AI 点数并填写账单说明。编辑复用发布表单，原子替换目录项并归档停用旧档位，玩家需重新启用；删除确认后从目录移除，历史账单、预留与已发送请求的原价格保留。显示实际发放/消费/预留、调用/失败/未知与 token 汇总；这些用量不是货币成本或利润。没有充值支付；AI 点数与桌游币独立。被引用的来源配置仍不能改写或删除，但可轮换/撤销密钥。详见 [官方 AI](official-ai.md)。

## 自定义徽章

后台「徽章设计」支持创建、编辑和启停自定义徽章，配置手动授予或正式对局指标的全部/任一组合。手动授予仍从账户管理进入；自动规则按历史记录实时计算，修改门槛会改变解锁资格。接口、迁移与展示边界见 [玩家徽章](badges.md#管理员自定义徽章050)。
