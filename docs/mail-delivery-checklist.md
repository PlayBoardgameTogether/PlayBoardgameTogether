# 邮件配置排错与真实收件验收

适用于注册验证码、本人绑定/换绑邮箱和找回密码。测试使用获得授权且能实际收信的邮箱；后台测试邮件受理、验证码申请成功与实际收件分别记录。

## 配置与排错

先由管理员在「系统维护 → 邮件设置」读取当前配置，确认已启用、已保存授权码及配置来源。网页保存立即用于后续发信；未保存的修改不能测试。后台保存过配置后，停用或清除授权码不会回退到旧环境配置。

| 现象 | 核对与处理 |
| --- | --- |
| 提示平台凭据加密未配置 | 由维护者核对实际运行进程是否加载原有 `MODEL_CREDENTIALS_KEY`。已有值必须沿用；不要为启用邮件重新生成或覆盖，避免历史凭据无法解密。首次加载环境按原维护流程处理 |
| 已保存的授权码无法解密 | 核对部署使用的原主密钥及备份来源；确认配置后，必要时由管理员重新保存供应商授权码。不清空数据库或输出密文排错 |
| 未启用、缺少授权码或邮件服务尚未配置 | 区分后台配置与旧环境回退；在后台启用并保存完整配置。授权码留空只会保留已有值，更换服务器、端口或账号须重新输入 |
| 连接、TLS 或认证失败 | 核对供应商允许的公网 SMTP 域名、账号、授权码及发件地址。465 为直接 TLS，587 强制 STARTTLS；检查部署环境到目标的网络连通性和证书，不关闭 TLS 校验、不改用私网/回环地址绕过限制 |
| 测试邮件已受理但没有收到 | 先查授权邮箱的垃圾邮件、隔离区和供应商投递记录，核对发件身份/域名验证及收件地址。平台不回显供应商原始错误；受理不能计为收件成功 |
| 保存或测试回复丢失 | 使用页面的「确认原保存请求」或「确认原测试请求」，复用原 requestId。测试处于 sending/结果未知时先查收件箱，不反复创建新请求；进程中断不会自动补发 |
| 发送过于频繁 | 注册同邮箱至少间隔 60 秒、每小时最多 5 封；发送失败也占额度。绑定/找回另有共享邮箱预算，后台测试全平台每分钟一次。等待对应窗口，不删额度记录或重启服务绕过 |
| 验证码错误、过期或已更新 | 使用最新一封对应流程的 6 位验证码；10 分钟有效、最多错 5 次。重发替换旧挑战，注册/绑定/找回不能互用；成功消费后不能重放 |
| 找回申请成功但没有邮件 | 找回接口对不匹配账号、冷却及投递失败保持统一申请提示，不能用响应判断邮箱归属。本人核对用户 ID 与已验证邮箱；未绑定邮箱的旧账号按维护者核验后的原 CLI 恢复流程处理 |

不要把 SMTP 授权码、平台主密钥、验证码、密码、session、CSRF 或完整请求头放入聊天、截图、日志或提交。供应商详细投递记录只在受控运维环境查看；验收记录保存时间、状态和脱敏结论。

## 收件闭环

1. 明确测试邮箱、允许的流程及发送范围。注册会创建正式账号，找回会修改测试账号密码并撤销会话；先确认使用专用测试账号。配置变更先核对 revision，保留既有凭据和环境。
2. 保存后台配置，向授权邮箱发送一次测试邮件。分别记录服务受理与收件人确认到达的时间；只有实际收到才继续把传输记为通过。
3. 在注册页申请验证码，由收件人直接在页面输入最新验证码，完成注册并用相同用户 ID 登录。不要在聊天中传递验证码或密码。
4. 对已明确授权的专用测试账号，按需要验收绑定/换绑及找回密码。找回成功后确认新密码能登录、旧密码及旧会话失效；不修改无关玩家账号。
5. 记录平台实际运行 SHA/版本、供应商受理/实际收件、页面流程和未覆盖范围。过期、重发、重复提交、频率限制及回滚可用隔离回归验证，不为了生产验收反复触发真实邮件或锁定玩家。

真实投递条件缺失时，交付受控回归与待办，保留“真实收件未验收”。本地注入传输和测试收件箱不验证供应商 SMTP、TLS、DNS、投递率或邮箱到达。

实现与限额以[账户认证](auth.md)为准；后台回执和操作说明见[管理员后台](admin.md)，部署环境加载见[部署指南](deployment.md)。
