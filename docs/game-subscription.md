# 官方游戏订阅

管理员打开 `/admin/catalog` 的「官方游戏订阅」，分别开启「自动添加新游戏」和「自动更新已安装游戏」，点击「保存订阅」。两项默认关闭；启用即授权后台自动校验、安装并上架该范围内的官方 ZIP 游戏。保存后安排一次同步，此后每小时检查；「立即同步」每分钟最多请求一次。

目录固定读取 PlayBoardgameTogether 平台仓库 main 的 `scripts/game-repositories/catalog.json`，新登记且有正式 Release 的在线游戏会被自动发现。逐游戏读取同组织仓库的最近 100 个 Release，忽略草稿和预发布，按数字版本选取每种玩法的最高版本；UNO 两种玩法分别处理。只接受已有独立游戏发布工作流生成的 `release.json`、精确版本 ZIP 及 SHA-256。管理员不能填写任意网址、凭据或脚本。未在这 100 条记录中的旧发布不会被搜索。

自动更新只替换新建房间使用的大厅入口，不迁移已开始的对局。已安装相同或更高版本时跳过，不覆盖精确版本；某游戏所有版本已下架时继续保持下架。内置游戏仍随平台审查、构建及部署更新，不支持通过本订阅独立热更新。关闭订阅不会卸载游戏。

“已安装相同或更高版本”只比较版本号，不重新下载并比对该已装版本的原始包摘要；不能据此证明与正式 Release 字节一致。[2026-11-06 清点](daily-release-audit-2026-11-06.md)已记录三个既存差异，旧安装与旧局继续保留；后续修订使用新版本，不覆盖旧包或修改历史摘要。

服务器使用原 ZIP 安装校验、QuickJS 规则、隔离 iframe 及安装事务。每包核对来源摘要与运行时清单的游戏 ID、版本；在提交前重新检查订阅 revision、策略、授权管理员的活跃角色及目录摘要。下载中关闭订阅或变更上架状态会使不符合新状态的安装失败。已经提交成功的安装保留；多游戏批次逐包提交，失败项不会回滚同批其他成功项。

授权持续绑定最后保存设置的管理员账户，不保存登录 token，不要求浏览器常开；该管理员退出登录不撤销订阅，账户被停用、删除或降为普通玩家后不能继续自动安装，其他管理员可重新保存设置恢复授权。手动保存和同步仍要求当前有效管理员会话、Origin、CSRF 和请求去重。

同步面板显示实际完成时间、下次检查、逐游戏结果和失败提示，每 5 秒刷新；关闭面板后停止轮询。网络回复丢失时保留原请求，可点「确认原保存请求」或「确认原同步请求」重试。重新打开页面会重新读取权威状态。

自动任务通过 PostgreSQL 会话 advisory lock 串行运行，多 API 实例只允许一个执行；网络请求有 20 秒期限，整个批次有 4 分钟期限，响应和 ZIP 流式读取限制大小并逐跳校验下载域名。服务关闭时取消下载并等待任务结束；进程异常退出释放数据库锁，面板显示中断，下一次到期或手动同步可恢复。不下载源码仓库 ZIP，不执行宿主 JS、npm 或 shell。

升级执行 `pnpm db:migrate` 应用 `037_game_subscription.sql`，正常备份数据库即可保留设置、最近同步结果和已安装游戏。安装器既有 100 个在线版本、10000 条安装回执配额继续适用，旧版本不会自动删除；接近配额时需要维护者处理。GitHub 公网不可达、限流、发布清单缺失/不匹配或校验失败会明确失败并保留原游戏，下一小时或手动请求可重试；不会使用源码包替代安装包。
