# 卡坦岛上传包

`online.catan@1.0.1`，经典基础版，3–4 人。海蓝岛屿棋桌与原创几何地块，支持真人、基础脚本 AI 和平台已配置的模型 AI。

```powershell
node scripts/package-catan.mjs
```

生成 `dist/game-packages/catan-1.0.1.zip`，包含自包含规则、隔离 HTML 棋桌及内嵌原创 PNG 图标/封面/背景。管理员从「游戏管理 → 上传游戏 ZIP」检查并审核上架，之后大厅可建房。无需新迁移、registry 分支或重启；源码目录不能直接压缩上传。未上传环境不会自动出现卡坦岛。

1.0.1 仅更新大厅封面：采用与现有游戏一致的深青背景和低饱和几何地块，960×540（16:9），去除重复标题与写实环境。原图标、详情背景、棋桌与规则保持；旧版本不能覆盖，管理员上传审核新版后新房间使用 1.0.1，旧局继续 1.0.0。生成方式与最终提示词见 [封面制作](art/cover-prompt.md)。

## 玩法

在自己的回合达到 10 分获胜：聚落 1 分、城市 2 分，最长道路/最大骑士军各 2 分，秘密胜利点牌每张 1 分。

- 随机先手和地形，19 地块，6/8 不相邻；9 个固定沿海港口。开局按先手顺序各建一聚落和一道路，再逆序各建一次；第二聚落提供相邻资源。每人最多 15 道路、5 聚落、4 城市，城市升级后聚落棋子归还。
- 双骰生产：聚落 1 张、城市 2 张，强盗地块不生产。每种资源共 19 张，不足多人需求则该种不发；只有一位领取者时发尽库存。
- 掷 7 时，超过 7 张者依座位顺序选择弃一半，向下取整；当前玩家移强盗并随机偷相邻有资源对手的一张。没有可偷对象则继续。
- 建造和交易采用官方建议的合并阶段，可交替执行。道路花木材/砖块各一；聚落花木材/砖块/羊毛/粮食各一；城市花 2 粮食和 3 矿石；发展牌花羊毛/粮食/矿石各一。聚落之间至少隔一条边，道路不能穿过对手建筑。
- 银行 4:1、通用港 3:1、专用港对应资源 2:1。双方资源组合报价可以接受、拒绝、还价；发起者和当前玩家可取消。只允许与当前玩家交易，双方必须提供不同种类资源，不能赠送或交易发展牌。
- 25 张发展卡：14 骑士、修路/丰收/垄断各 2、胜利点 5。新买的行动牌本回合不能使用，每回合最多一张行动牌，掷骰前也可使用。骑士移强盗；修路最多免费修两条，受可用道路限制；丰收取两张银行资源，仅剩一张时取一张；垄断拿取对手全部指定资源。新买胜利点可立即计分，获胜前不公开给对手。
- 最长道路至少 5 条，不重复边，分叉取最长路线，对手建筑截断。最大骑士军至少使用 3 骑士。平局由原持有者保留；原持有者退出领先行列后，只有唯一最长者获奖，其他平局暂不授予。只有当前回合玩家才能获胜。

规则依据：[官方基础版规则与手册](https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf)、[官方基础版 FAQ](https://www.catan.com/faq/basegame)。数字版选择随机先手、资源弃牌串行确认、指定对象报价和合并交易/建设阶段。没有扩展、计时赛或官方素材。

## 棋桌交互

岛屿为视觉焦点，本人资源在底部，玩家总资源/发展牌数量和公开分数在顶部。建造、发展卡、玩家/银行交易、弃牌和规则各自在按需弹窗中处理。点击合法交点、边或地块 → 预览 → 确认；选择不提交，提交中禁止重复操作。手机可用「选择位置」列表查看相邻地块与点数，也可放大棋盘后拖动平移，「全岛」复位。

聚落/道路/城市分别用形状及玩家颜色区分，资源同时提供名称与数量，骰子概率点数辅助识别。键盘可聚焦合法位置并按 Enter/空格选中。放大/平移及表单草稿只在当前棋桌保存；权威版本或身份变化清除选择和弹窗，刷新恢复服务器已提交状态。只读回放没有可提交动作。

## 维护与边界

`shared.txt` 仅包含公开地图拓扑、资源名称和成本，同时嵌入服务端和浏览器。`server.txt` 拥有秘密资源组成、发展牌、确定性 RNG、规则和守恒存档验证；View 只包含自己的资源/发展卡，其他玩家只有数量及公开信息。公开偷窃事件不包含资源身份，报价不携带对方手牌组成。平台继续拥有身份、控制权、锁、事务、回执去重、revision、恢复与精确版本回放。

基础 AI 使用有界候选：优先建设、使用发展牌和有用银行交易，能处理起始摆放、弃牌、强盗和免费修路；不穷尽谈判，接受有足够资源的报价，策略不保证最佳。真人可自由提交合法组合报价/还价和弃牌；服务器独立校验。未验证真实外部模型调用。

本包不提供平台音效、可切换图包或交互教程。同版本安装后不可覆盖；规则/棋桌更新必须提升 manifest 版本及打包输出版本，旧局继续使用精确旧包。
